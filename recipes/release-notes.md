Write release notes for everything since the last git tag.

Write for the people who use this project, not for the people who built it: what they can do now, what works better, what they need to change on their side. Group by what matters most to them, not by commit order. Skip internal refactors unless they change behavior.

Short sentences, no hashes, no jargon that only the codebase knows. Save the result as a document in this project and link it.
